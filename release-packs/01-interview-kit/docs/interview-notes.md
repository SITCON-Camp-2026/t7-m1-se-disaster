# 使用者訪談紀錄

> 這份文件可以由 Codex 先產生草稿，但你必須刪除、修改或補充。請不要直接把 AI 輸出當成最後結論。

## 我的 Phase 0 prototype 現況

請用 3–5 句描述你目前的資訊整理工作台：

- 這個工作台把原始資訊、來源與查核狀態放在同一個畫面，讓使用者先看到資料的混亂與不確定。 
- 目前畫面能顯示未確認、待人工確認與品質指標，但仍沒有把「可否直接成為任務」做成更清楚的分界。
- 使用者可以在原始資訊與整理工作台之間切換，並看到某些資料需要更進一步確認。

## Persona 1：回報者

### 我想完成的事

- 我想快速把我看到或聽到的情況送出去，不想被表單卡住。
- 我想讓後續的人知道我只是轉述，不是已確認的事實。

### 我看不懂的地方

- 我不確定哪些標籤代表「我已確認」，哪些只是「還沒確認」。
- 我看不出來哪些資訊會被當成可執行任務，哪些只是暫時留存。

### 我最怕的錯誤

- 我只是轉述，系統卻把它當成已確認的行動依據。
- 我沒有填完整資訊，系統卻自動補成看起來很完整的內容。

### 我不敢直接相信的資訊

- 任何沒有明確來源或時間的資訊。
- 任何聽起來像官方但沒有說明確認方式的資訊。

### 我希望系統提醒我的事

- 我的資訊是不是只是一份轉述。
- 我是否需要特別說明「我不確定」這件事。

### 我想反問開發者的一個問題

- 如果我只是提供線索，系統會不會真的把它當成可以採取行動的任務？

## Persona 2：資訊整理者

### 我想完成的事

- 我想快速把混亂資訊分成「可相信、需確認、不能直接用」三類。
- 我想保留原始文字，避免後續協作者把推測當成事實。

### 我看不懂的地方

- 我不確定哪些資訊是原始內容，哪些是 UI 上的判斷。 
- 我看不出來介面是否真的把查核狀態與任務狀態分開。

### 我最怕的錯誤

- 模糊資訊被直接當成任務。
- AI 或 UI 把「可能」寫成「已確認」。
- 沒有留下為什麼這筆資料不能直接使用的理由。

### 我不敢直接相信的資訊

- 社群轉錄、二手訊息與沒有官方確認的內容。
- 有衝突或缺乏時間上下文的資訊。

### 我希望系統提醒我的事

- 這筆資訊是由誰提供的、是否為現場回報、是否需要人工確認。
- 哪些地方是目前沒有辦法確認的。

### 我想反問開發者的一個問題

- 如果資訊還不能用，系統應該要如何明確阻止人們把它當成任務？

## Persona 3：行動者

### 我想完成的事

- 我想知道哪些資訊現在適合採取行動，哪些應該先停下來。
- 我想避免因為錯誤資訊而跑錯地方或做錯事。

### 我看不懂的地方

- 我不知道哪些資訊已經過確認，哪些只是被標成「待確認」。
- 我看不出來目前這筆資訊是否適合直接派人或發送資源。

### 我最怕的錯誤

- 把未確認資訊當成已確認。
- 走到現場才發現任務已經不成立或狀況已不同。

### 我不敢直接相信的資訊

- 缺少時間、地點或來源說明的資訊。
- 看起來很像現場更新，但其實沒有足夠證據的內容。

### 我希望系統提醒我的事

- 這筆資訊可能過期、衝突或缺乏足夠上下文。
- 這筆資訊目前不適合作為行動依據。

### 我想反問開發者的一個問題

- 如果這筆資訊不能直接行動，畫面是否應該更明確地阻止我往下走？

## 人類補充

請寫下 Codex 沒有注意到，但你覺得重要的觀察。

- 三個 persona 都非常在意「是否能直接行動」這件事，這比單純看起來好不好看更重要。
- 使用者很容易把「來源」誤當成「已確認」，所以介面需要把來源與查核狀態拆開呈現。
- 這個 prototype 目前已經有助於暴露資料品質問題，但還不夠清楚地告訴使用者「現在不能做什麼」。
